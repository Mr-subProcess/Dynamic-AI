# Dynamic AI → DRNC-Q function map

| Dynamic AI role | PC source/runtime | QPC circuit template | Meaning / boundary |
|---|---|---|---|
| Matrix arithmetic | `dot`, `matvec`, `transpose_matvec`, `vec_add`, `vec_scale`, `vec_hadamard` in `modules/matrix_core.drq` | `matrixEdge(theta,source,destination)` | PC operates on classical numeric lists; QPC translates learned parameters into gate angles. These are not mathematically identical operators. |
| Recurrent memory | `W_memory` and `memory` vector each example | `memory0..memory2` logical wires | PC has a recurrent classical state. QPC is a finite circuit template and does not contain an unrolled training-time recurrent loop. |
| Learnable weights | `adapt_matrix` with clipped local-delta outer products | Twelve diagonal checkpoint values inserted by `scripts/generate_qpc_source.sh` | A simple hybrid parameter-transfer bridge, not exact quantum matrix multiplication. |
| Superposition link | `superposfonk(pi()/11)` modulates branch gain through EVET/HAYIR probabilities | `superposfonk(pi()/7)` attention/control qubit | DRNC-Q runtime constructs relational sectors; no application-level bit-string state literals are provided. |
| Entanglement relation | `donfonk(sensory_link,memory_link)` plus a global `donfonk()` pair | `donfonk(sensory0,sensory1)` plus `donfonk()` global pair | Uses the constructors' DRNC-Q semantics; entanglement does not enable controllable classical signalling. |
| Zerya branch | `zeryafonk(attention_link)` and `zeryafonk(global_pair)` used by relational checks; global branch gain influences classical propagation | `zeryafonk(sensory2)` and `zeryafonk(memory1)` branch wires | Branch sectors are generated by DRNC-Q. Their role in the PC matrix network is a design-level coupling, not a physical neural synapse claim. |
| Modular evolution | `evrimfonk` steps the shared dimensionless modular parameter during train and online updates | `evrimfonk` and `moduleradim` emit phase evolution | `s` is dimensionless and not calibrated seconds. |
| Online feedback | `Dynamic_AI_Online_PC.drq` loads a checkpoint, performs labelled updates and saves it | Updated matrix diagonals become the next QPC build angles | Hybrid training occurs on the PC; hardware-in-the-loop training is not implemented. |
| Measurement and readout | Local simulator constructors and checks are used for PC relations | `measure`, `measure_all`, conditional `if/else` feed-forward | QPC results become physical shot samples only when run by a compatible real device/driver. |
